# 导入格式规范 v1

**网站只认这一种格式。** 任何词源，先整理成本规范，再上传。格式不对就不收，收下的一定能用。

---

## 一、文件要求

| 项 | 要求 |
|---|---|
| 格式 | CSV（逗号分隔） |
| 编码 | **UTF-8**（Excel 另存为 CSV 默认是 GBK，中文会变乱码，务必选「CSV UTF-8」） |
| 首行 | 必须是表头，字段名固定 |
| 列顺序 | 固定，不许调换 |
| 文件名 | 随意，建议 `词库名.csv` |

---

## 二、列定义

| 列 | 必填 | 说明 |
|---|---|---|
| `word` | 是 | 英文词条，**统一小写**，不要带编号、不要带序号 |
| `meanings` | 是 | 中文释义，规则见下 |
| `phonetic` | 否 | 音标，含斜杠 `/ˈwɜːd/`，没有就留空 |
| `note` | 否 | 备注，比如「六级高频」「易混词」，留空亦可 |

---

## 三、meanings 的写法（最关键）

一句话规则：**`|` 分隔不同义项，`、` 分隔同一义项里的近义说法。**

```
n.地址、住址|v.处理、应对|v.向……致辞
```

拆解：

- `n.` `v.` `adj.` `adv.` `prep.` 是词性前缀，可省略
- `|` 前后是**不同的义项**，答对一个就算对
- `、` 连接的是**同一个义项的不同说法**，答其中任意一个都算对
- 一个义项写清楚就行，不要堆长句，不要写「某人做某事的样子」这类无法判定的解释

**为什么这样设计：** 判分时 `|` 划出「得分点」，`、` 划出「可接受的同义答案」。你答「处理」和答「应对」都判对，因为你确实说对了。结构清楚，判分就不会乱。

---

## 四、示例

```csv
word,meanings,phonetic,note
address,n.地址、住址|v.处理、应对|v.向……致辞,/əˈdres/,六级高频
serendipity,n.意外发现美好事物的运气、机缘巧合,/ˌserənˈdɪpəti/,
bludgeon,n.大头短棍、棍棒|v.用棍棒击打|v.胁迫,/ˈblʌdʒən/,易混词
```

---

## 五、网站会检查什么

上传后立刻校验，任何一条不过就整份退回，并指出**第几行、哪一列、什么毛病**：

1. 表头是否为 `word,meanings,phonetic,note`
2. `word` 是否为空、是否含非英文字符（连字符、空格、撇号除外）
3. `meanings` 是否为空
4. 是否出现重复词条（重复的会自动合并义项，并计入报告）
5. **行数是否与你填写的「原始词数」一致**（防止 AI 整理时悄悄漏词）
6. 释义里是否出现占位符 `???`（说明当初没查到，需要人工确认）

校验通过后：进入背诵，词源与记忆法由网站按词条自动生成并缓存，**不需要你准备**。

---

## 六、宁缺毋滥

某条词查不到可靠中文释义时，`meanings` 填 `???`，不要瞎编。
编出来的释义会污染判分标准，比少一个词严重得多。校验器会把这些行单独列出来给你确认。
